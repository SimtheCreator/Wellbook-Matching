# Wellnista Matching Logic (Algorithm V1)

เอกสารฉบับนี้อธิบาย **ระบบการจับคู่ (Matching Logic)** ระหว่างผู้ใช้งาน (User) และกิจกรรมเพื่อสุขภาพ (Wellness Activities) ซึ่งถูกนำไปใช้ใน `calculateMatch()` ของไฟล์ `WellnistaAssessment.jsx` 

ระบบนี้ใช้พื้นฐานคณิตศาสตร์เรื่อง **Euclidean Distance (ระยะห่างในปริภูมิ N มิติ)** เพื่อหาระยะห่างระหว่าง "เวกเตอร์ของผู้ใช้" และ "เวกเตอร์ของกิจกรรม" ยิ่งระยะห่างน้อย แปลว่ากิจกรรมนั้นเหมาะสมกับผู้ใช้มากที่สุด

---

## 1. แกนชี้วัดทั้ง 5 มิติ (The 5-Dimensional Vector)
กิจกรรมและผู้ใช้งานจะถูกประเมินผ่าน 5 แกนหลัก ได้แก่:
1. **P (Physical Energy):** พลังงานกาย / ความพร้อมของร่างกาย
2. **M (Mental Energy):** พลังงานใจ / สภาพจิตใจ
3. **S (Social Engagement):** ความต้องการปฏิสัมพันธ์กับผู้อื่น
4. **N (Novelty / Exploration):** ความต้องการเปิดรับสิ่งใหม่
5. **G (Growth / Deep Work):** ความต้องการพัฒนาตัวเองเชิงลึก

ผู้ใช้ทุกคนจะเริ่มต้นด้วยเวกเตอร์ **[ P: 0, M: 0, S: 0, N: 0, G: 0 ]** 
เมื่อตอบแบบสอบถามในแต่ละข้อ คะแนนในมิติต่างๆ จะถูกบวกหรือลบ ดังนี้:

## 2. การคำนวณคะแนนผู้ใช้งาน (User Vector Calculation)

### Step 2: สภาพร่างกายและจิตใจ (Physical & Mental State)
* **Physical (อาการทางกาย):**
  * `pain` (ปวดเมื่อย): `P -2`
  * `fatigue` (อ่อนเพลีย): `P -3`
  * `normal` (ปกติ): `P +1`
* **Mental (อาการทางใจ):**
  * `stress` (เครียดสะสม): `M -3`
  * `insomnia` (นอนไม่หลับ): `M -4`, `P -2`
  * `burnout` (หมดไฟ): `M +2`, `N +3` *(ต้องการความตื่นเต้น/เปลี่ยนบรรยากาศ)*
  * `normal` (แจ่มใส): `M +1`
* **Negative Feelings (อารมณ์ลบ):**
  * `tension` (ตึงเครียด/กระวนกระวาย): `M -3`
  * `mood` (ซึมเศร้า/หม่นหมอง): `M -4`
  * `aches` (ปวดหัว/ปวดตา): `P -3`
  * `normal` (ปกติ): `P +1`, `M +1`

### Step 3: สัญญาณชีพจรและตัวชี้วัดสุขภาพ (Biomarkers)
* **Resting Heart Rate (จังหวะชีพจรขณะพัก):**
  * `high` / `veryhigh` (สูงกว่า 80+): `P -3`, `M -2` *(ร่างกายอ่อนล้า/เครียดแฝง)*
  * `normal` / `low` (ต่ำกว่า 80): `P +1`
* **Sleep (เวลานอนเฉลี่ย):**
  * `less5` (< 5 ชม.): `P -4`, `M -3`
  * `6to7` (6-7 ชม.): `P -1`, `M -1`
  * `more9` (> 9 ชม.): `P +2`, `M +1`
* **Exercise (ความถี่การออกกำลังกาย):**
  * `none` (แทบไม่ได้ออก): `P -2`
  * `3to4` (3-4 วัน/สัปดาห์): `P +2`
  * `5plus` (5 วันขึ้นไป/สัปดาห์): `P +4`
* **Stress Level (ระดับความเครียด 1-10):**
  * `1-3` (น้อย): `M +1`
  * `4-6` (ปานกลาง): `M -1`
  * `7-8` (สูง): `M -3`
  * `9-10` (รุนแรง): `M -4`, `N -2` *(ไม่พร้อมรับสิ่งใหม่ที่หนักเกินไป)*

### Step 5: บุคลิกภาพและไลฟ์สไตล์ (Personality & Environment)
* **Style (ความชอบ - เลือกได้หลายข้อ และคะแนนจะบวกสะสมกัน):**
  * `active` (ชอบขยับตัว): `P +4`
  * `passive` (เน้นผ่อนคลาย): `P -4`, `M -2`
  * `creative` (ชอบงานคราฟต์/ศิลปะ): `N +4`
  * `growth` (เน้นจิตวิญญาณ/พัฒนาตัวเอง): `G +4`, `M +2`
  * *(ตัวอย่าง: ถ้าเลือกทั้ง `active` และ `creative` ผู้ใช้จะได้คะแนน `P +4` และ `N +4` รวมกันเข้าไปในเวกเตอร์)*
* **Openness (ความเปิดรับสิ่งใหม่):**
  * `low` (ชอบความคุ้นเคย): `N -4`
  * `high` (ชอบลองสิ่งใหม่): `N +4`
* **Social (การเข้าสังคม):**
  * `solo` (ทำคนเดียวเงียบๆ): `S -4`
  * `smallgroup` (กลุ่มเล็กๆ): `S +1`
  * `networking` (พบปะเพื่อนใหม่): `S +4`

## 3. เงื่อนไขข้อห้ามและการคัดกรอง (Clinical Screening / Vetoes)
ระบบจะทำการกรอง (Filter out) กิจกรรมที่ **"เป็นอันตราย"** ต่อสุขภาพของผู้ใช้ออกไปทันที หากผู้ใช้เลือกข้อจำกัดด้านสุขภาพตรงกับ `veto` ของกิจกรรมนั้นๆ
* ระบบเช็คว่า: มี Veto ใดในกิจกรรมที่ตรงกับ `redFlags` (PAR-Q+) ของผู้ใช้หรือไม่
* หากตรงกัน **กิจกรรมนั้นจะถูกตัดออกจากผลลัพธ์ทันที** และขึ้นป้ายเตือน (Warning Banner)
* หากผู้ใช้เลือก `athome` (ทำที่บ้านได้) กิจกรรมประเภท `onsite` จะถูกตัดออกทั้งหมด

## 4. การคำนวณคะแนนความแมตช์ (Distance & Score Calculation)

### 4.1 Euclidean Distance
ระบบใช้สูตรเรขาคณิตวิเคราะห์หาระยะห่าง (Distance) ระหว่าง "ผู้ใช้งาน" และ "กิจกรรม" แต่ละตัว:
```javascript
let pDiff = Math.pow(uv.p - act.vector.p, 2);
let mDiff = Math.pow(uv.m - act.vector.m, 2);
let sDiff = Math.pow(uv.s - act.vector.s, 2);
let nDiff = Math.pow(uv.n - act.vector.n, 2);
let gDiff = Math.pow(uv.g - act.vector.g, 2);

let distance = Math.sqrt(pDiff + mDiff + sDiff + nDiff + gDiff);
```

### 4.2 Score Conversion (แปลงระยะห่างเป็น % ความแมตช์)
* กำหนดให้ระยะห่างเป็น `0` หมายถึงแมตช์ 100%
* ใช้สูตร: `score = Math.max(0, 99 - (distance * 3.5))` 
  *(คูณ 3.5 เป็นค่าปรับจูน (Weight) เพื่อกระจายกราฟเปอร์เซ็นต์ให้เหมาะสม)*
* **Bonus Point:** หากสภาพแวดล้อมที่ชอบตรงกับกิจกรรม (`state.env === act.env`) เช่น indoor ตรงกับ indoor จะบวกคะแนนเพิ่ม **+2%**
* สุดท้ายจำกัดเพดานคะแนน (Cap) ไม่ให้เกิน **99%**

### 4.3 Ranking & Fallback
* กิจกรรมที่ผ่านการคัดกรอง จะถูกนำมาเรียงจาก **คะแนนมากไปน้อย** 
* หน้าผลลัพธ์จะแสดง Top Match 1 อัน และ Alternatives (ตัวเลือกรอง) สูงสุด 3 อัน
* **Fallback:** หากโชคร้ายผู้ใช้มีข้อจำกัดด้านสุขภาพ (Veto) จนโดนตัดออกทุกกิจกรรม ระบบจะบังคับยัดกิจกรรม **Yoga** ให้ 1 ตัวที่คะแนน `75%` เพื่อไม่ให้หน้าผลลัพธ์ว่างเปล่า

## 📌 บทสรุปเพื่อนำไปใช้งานต่อ (Checklist)
1. **เพิ่มกิจกรรมใหม่:** แค่กำหนด Veto และสร้างค่า Vector (P, M, S, N, G) ของกิจกรรมนั้นลงใน `clinicalData` ระบบจะคำนวณให้ทันที
2. **ปรับความแข็ง/อ่อน ของคำแนะนำ:** หากรู้สึกว่าแอปแนะนำ % ง่ายเกินไป ให้ปรับตัวคูณ `3.5` (เช่น เปลี่ยนเป็น `4.0` คะแนนโดยรวมจะลดลง)
3. **การเพิ่มสเกลคำถาม:** หากในอนาคตมีคำถามใหม่ ให้กำหนดค่า `+/-` เข้าไปใน 5 แกนนี้ (P, M, S, N, G) ได้เลย โดยไม่ต้องแก้สมการ Euclidean Distance
